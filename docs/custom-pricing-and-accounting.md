# คอร์ต ราคา Promotion และบัญชี

ระบบใช้ค่าของ Ultra เดิมเมื่อยังไม่บันทึกกฎใหม่ ไม่เพิ่มคอร์ตหรือเปลี่ยนราคาของร้านจริงโดยอัตโนมัติ ข้อมูลกฎใหม่อยู่ที่ `commerce_settings/current.commerce` แยกจากราคาพื้นฐานสาธารณะ `system_settings/pricing` และประวัติการแก้ไขอยู่ที่ `commerce_settings_history` การบันทึกต้องใช้บัญชีบทบาท `owner`

## ตั้งค่าร้านและตัวอย่าง 4 คอร์ต

1. เปิดหน้า Admin → แท็บราคา/โปรโมชัน → **คอร์ต ราคา และ Promotion**
2. ใช้คอร์ตเดิมและเพิ่มอีก 3 คอร์ต ตั้งชื่อ เวลาเปิด/ปิด และสถานะเปิดใช้งาน
3. เพิ่มกฎราคา เลือกคอร์ต วัน เวลา และช่วงวันที่ ระบุราคาชั่วโมงและครึ่งชั่วโมง
4. เพิ่ม Promotion แบบลดบาท ลดเปอร์เซ็นต์ หรือราคาสุทธิต่อการจอง พร้อมยอด/นาทีขั้นต่ำ เพดานส่วนลด และอนุญาตใช้ Coupon ร่วมได้หรือไม่
5. ทดลองราคาจากฟอร์มก่อนบันทึก แล้วเปิดตารางเวลาของแต่ละคอร์ตในหน้า Admin การเปิดใช้งานคอร์ตไม่ได้สร้างตารางเวลาว่างให้อัตโนมัติ

API หน้าลูกค้าส่งเฉพาะชื่อร้านและคอร์ตที่เปิดใช้งาน ส่วนกฎเต็มอ่านผ่าน API สำหรับ Owner เท่านั้น หากเคยบันทึกกฎแบบชั่วคราวไว้ใน `system_settings/pricing.commerce` การบันทึกจาก Owner ครั้งถัดไปจะย้ายไปเอกสารใหม่และลบฟิลด์เดิมพร้อมกัน โดยไม่เปลี่ยนราคาพื้นฐาน

คอร์ตที่เคยบันทึกแล้วปิดใช้งานได้ แต่ลบหรือเปลี่ยนรหัสไม่ได้ เพื่อเก็บการอ้างอิงของรายการเก่า ลูกค้าเลือกคอร์ตได้จากหน้าจองและหน้าเวลาว่าง แคชเวลาว่างแยกตามคอร์ต การย้ายคอร์ตผ่านหน้าเลื่อนจองคงยอดเดิมไว้

สำหรับ Prototype ของลูกค้า ให้ใช้ Firebase project และการตั้งค่าบัญชีของลูกค้าแยกจาก Ultra โค้ดนี้รองรับหลายคอร์ตภายในร้านเดียว ยังไม่ได้เพิ่มระบบหลายร้านในฐานข้อมูลเดียวหรือเปลี่ยนแบรนด์/บัญชีรับเงินทั้งเว็บไซต์

## วิธีคำนวณ

`ราคาคอร์ต → Promotion อัตโนมัติหนึ่งรายการ → Coupon หนึ่งโค้ด → ยอดชำระ`

- กฎราคาที่ตรงเงื่อนไขแทนราคาพื้นฐานของช่วงเวลานั้น เลือกลำดับสูงสุดก่อน หากเท่ากันเรียงรหัสกฎ ราคาเฉพาะต้องครอบคลุมทั้งช่วงย่อย 30/60 นาทีจึงใช้ได้
- Promotion ต้องครอบคลุมเวลาจองทั้งหมด เลือกกฎที่มีสิทธิ์และลำดับสูงสุด ส่วนลดบาทและราคาสุทธิคิดต่อการจอง ไม่คูณจำนวนชั่วโมง
- วันที่/วันในสัปดาห์ของกฎใหม่อ้างอิงวันใช้สนามตามเวลาไทย ช่วงวันที่รวมวันเริ่มและวันสิ้นสุด กฎวันหยุดอ้างอิงตารางวันหยุดเดิม
- Coupon ตั้งระยะเวลาได้ 30–180 นาที หรือไม่จำกัดระยะเวลา เลือกคอร์ตเฉพาะหรือทุกคอร์ตได้ ข้อกำหนดเจ้าของโค้ด จำนวนครั้ง และการจองสิทธิ์ยังใช้ระบบเดิม ส่วน Event Pass ยังคง 60 นาที
- ราคาพื้นฐานและโปรโมชันเดิมยังเป็น fallback หากไม่มีกฎใหม่ การใช้โปรโมชันใหม่ทับราคาจากโปรเดิมเป็นส่วนลดเพิ่ม จึงควรตรวจตัวอย่างก่อนบันทึก
- โปรโมชันใหม่ใช้กับการเช่าคอร์ต คาบโค้ชยังคงราคาคาบและเงื่อนไขแพ็กเกจเดิม กฎราคาคอร์ตใช้คำนวณส่วนแบ่งคอร์ตของ Coach Add-on v2 แต่ไม่ได้ลดราคาคาบด้วยโปรโมชันใหม่
- ข้อจำกัดระยะเวลาและช่วงครึ่งชั่วโมงเดิมยังอยู่ ไม่รองรับการจองข้ามเที่ยงคืน

ตัวอย่าง: คอร์ต 400 บาท × 2 ชั่วโมง = 800 บาท → โปร 10% ลด 80 บาท → Coupon ลด 50 บาท → ชำระ 670 บาท

## บัญชีและประวัติราคา

รายการใหม่เก็บ `pricingSnapshot` ซึ่งมีราคาก่อนส่วนลด ส่วนลด Promotion ส่วนลด Coupon ยอดสุทธิ กฎที่ใช้ และรุ่นการตั้งค่า การแก้กฎภายหลังไม่เปลี่ยนรายการเดิม Server คำนวณราคาและตรวจซ้ำขณะจอง หากราคาที่ลูกค้าเห็นไม่ตรงต้องขอราคาใหม่

หน้า Finance แสดงยอดก่อน/หลังส่วนลดและสรุปแยกคอร์ต เลือกเดือนได้ตามวันใช้สนามหรือวันที่รับเงิน (`paidAt`) รายการเก่าที่ไม่มี `paidAt` จะไม่อยู่ในมุมมองวันที่รับเงิน ไม่มีการเดาวันรับเงินย้อนหลัง รายการลดเหลือศูนย์ยืนยันได้โดยไม่สร้างรายรับเงินสด

ใบเสร็จใช้ราคาก่อนส่วนลดและส่วนลดรวมจาก snapshot ยอดสุทธิตรงกับยอดชำระ การแยกรายการเลื่อนจองปันส่วนยอดและส่วนลดโดยรักษายอดรวม หากมีใบเสร็จใช้งานอยู่ ต้องจัดการเอกสารเดิมก่อนแยกรายการเพื่อไม่ให้ออกซ้ำ

## สลิปและการต่อ API ภายหลัง

ยังใช้การแนบสลิป ตรวจเบื้องต้น และแอดมินอนุมัติตามเดิม ไม่มีการเรียกบริการตรวจสลิปภายนอก ไม่มี API key และเปิดโหมดอัตโนมัติไม่ได้ การอนุมัติใหม่เก็บผู้อนุมัติ เวลา และ `paymentApproval.mode = manual`

จุดเตรียมต่อบริการอยู่ที่ `api/_lib/payment-verification.js` เมื่อซื้อ API แล้วจึงเพิ่ม adapter ฝั่ง Server เพื่อตรวจบัญชีผู้รับ จำนวนเงิน เวลาการโอน และเลขอ้างอิงที่เชื่อถือได้ พร้อมป้องกันเลขอ้างอิงซ้ำใน transaction ก่อนใช้ขั้นตอนเปลี่ยนสถานะชำระเงินเดียวกัน ผลตรวจจาก Browser ไม่ใช่หลักฐานชำระเงิน

## การตรวจสอบในเครื่อง

ผลตรวจวันที่ 23 กันยายน 2026: **762 tests ผ่านทั้งหมด จาก 47 ไฟล์** รวม rules security 62 tests และ rules cutover compatibility 3 tests โดยไม่มีการยกเว้นชุดทดสอบ ใช้ rules ที่ผู้ใช้แนบและ Firestore Emulator ในเครื่อง ยังไม่ใช่การทดสอบ staging หรือหลักฐานว่า rules นี้ถูก deploy แล้ว

ใช้ Firestore Emulator เท่านั้นสำหรับ integration tests:

```powershell
$env:FIRESTORE_EMULATOR_HOST = '127.0.0.1:8185'
$env:GCLOUD_PROJECT = 'demo-emulator'
$env:RULES_FILE = 'C:\path\to\firestore.rules' # ระบุไฟล์ rules ที่ต้องการตรวจ
node node_modules/vitest/vitest.mjs run
```

กำหนด `RULES_FILE` เป็นไฟล์ภายนอก repository ตามแนวทางเดิมของโครงการ เพื่อรันทั้ง `firestore-rules.test.mjs` และ `rules-cutover-compat.test.mjs` โดยไม่ยกเว้น tests สิทธิ์ฐานข้อมูล ส่วน `GCLOUD_PROJECT` และ `FIRESTORE_EMULATOR_HOST` ต้องชี้ Emulator ในเครื่องเท่านั้น

Rules ที่ผู้ใช้แนบวันที่ 23 กันยายน 2026 เปิดอ่าน `system_settings/pricing`, `available_slots` และ `booking_slots` ส่วน collection อื่นที่ไม่ได้ระบุใช้ catch-all deny จึงปิดทั้งการอ่านและเขียน `commerce_settings` / `commerce_settings_history` อยู่แล้ว ไม่ต้องเพิ่มสิทธิ์ Client ให้สอง collection นี้ Owner จัดการผ่าน API ฝั่ง Server

ชุดทดสอบเพิ่มครอบคลุมการอ่าน/สร้าง/แก้ไข/ลบกฎและประวัติจากผู้ไม่ล็อกอิน ลูกค้า และบัญชีที่มี Owner claim รวมถึงการอ่านเวลาว่างแยกทั้ง 4 คอร์ตและการห้ามแก้หลักฐานอนุมัติชำระเงินโดยตรง
